# 12 · 繁简与中英：检索应对方案

用户用现代简体中文提问；入库原文却是 **简体、繁体、英文** 混存。若不处理，会出现「库里有全书，关键词对不上」的假阴性，或「为了对上而改写原文」的假阳性。

本文件是强制规范。实现见 `scripts/zh_fold.py` 与 `scripts/retrieve.py`。

---

## 1. 铁律（先钉死）

| 层 | 用什么文字 |
|----|------------|
| **入库 / 引用 / 校验** | **永远用底本原文**（简就简、繁就繁、英就英） |
| **检索匹配** | 折叠键 + 确定性扩词 + **允许模型改写查询**（见 §3.5 / §4.5）；只为打分，不改写入库 |
| **对用户作答** | **中文**；若引英/繁，可附「意译」，且必须标明非原文 |

禁止：

- 把通鉴繁体改写成简体再当「原文依据」
- 把 Marriott 英译意译成中文再当马基雅维利「原文」
- 为迁就检索，生成一条库中不存在的简体句子去过 Verifier
- 把「模型改写后的繁体/英文查询句」当成典籍原文引用

Verifier 仍校验：**引号内字符串必须是 chunk 原文的连续子串**（不做繁简折叠、不做回译比对）。

---

## 2. 语料现状（事实）

| 书 | 底本脚本 | 用户典型问法 |
|----|----------|--------------|
| 实践论、矛盾论、史记简体 | 简体中文 | 简体 |
| 孙子、道德经（维基） | 简体为主 | 简体 |
| **资治通鉴（kanripo）** | **繁体为主** | 简体（玄武门、司马光、赤壁） |
| 君主论、沉思录 | **英文** | 简体中文 |

因此有两类错配：

1. **简 ↔ 繁**：门/門、司马/司馬、纪/紀  
2. **中 ↔ 英**：爱戴畏惧 ≠ loved / feared  

---

## 3. 繁简应对（简 ↔ 繁）

### 3.1 匹配折叠键

对「查询词」和「窗口文本」都做同一变换后再 `in` 匹配：

```text
fold(s) = to_simplified(s)   # 字符级繁→简；英文 lower()
```

例：

- 用户：`玄武门` → fold = `玄武门`  
- 库中：`玄武門` → fold = `玄武门` → **命中**  
- Pack 里 `text` 仍是 `玄武門...`（原文）

### 3.2 查询扩词（双写）

每个中文检索词同时保留：

- 用户原词  
- `fold(原词)`  
- 必要专名的繁体互逆（如 通鉴 / 通鑑）

避免只折叠窗口、不折叠「司马光 vs 司馬光」这类整词。

### 3.3 不做什么

- **不**把 14MB 通鉴转成简体另存一份当真相源（版本分叉、校验崩溃）  
- **不**在 Phase A 依赖必须安装 OpenCC；无 OpenCC 时用内置繁简对照表  
- Phase B 可加 OpenCC / zhconv 提高人名、异体字覆盖（於/于、裏/里、著/着）

### 3.4 异体与通假（降级）

古籍另有异体（劒/剑）、通假（说/悦）。Phase A **不**做通假等价。  
字符折叠打不中时，**先走 §3.5 模型查询改写**，再拒引。  
仍未命中才 L0：说明「或为异体/通假/别名未覆盖」，建议换关键词或指定卷次。  
Phase C 可加「专名别名表」（玄武门事件 → 卷一九一 等）。

### 3.5 模型查询改写（繁体侧，Skill 驱动）

用户几乎总是**简体提问**。当目标书箱含繁体底本（尤其通鉴），且满足任一条件时，Skill **可以**产出检索专用改写再二次检索（权宜，见 §3.6）：

触发条件（满足其一即可）：

1. Router 打开 `history` / 明确点名通鉴、繁体底本  
2. 第一次确定性检索（fold + 扩词）对该书 `low_confidence` 或 0 命中  
3. 问题含事件/制度语义，难以靠 2–3 字 n-gram 对上古文措辞  

改写产出（只用于 `--extra-queries`，**不是原文**）：

| 产出 | 用途 |
|------|------|
| 1–3 条**繁体**检索短句 | 更接近史书措辞（例：簡「玄武门之变」→ 繁「玄武門之變」「太子建成」） |
| 可选关键词列表 | 人名、年号、地名的繁体形 |

约束：

- 改写可以「等价转述意图」，**禁止编造库中未必存在的整句「原文」**  
- Pack 必须记录 `rewritten_queries`，便于审计  
- 命中后引用仍贴库中繁体窗口原文  
- 改写是 **Phase A 权宜**，倾向性见 §3.6；不得把「模型爱用的范畴」当成库中主证据来源

### 3.6 改写的倾向性（已知债，忠于库）

模型**装不下全书**。Pass-2 改写用的是模型先验范畴（群众路线、伐交、loved/feared…），不是库里实际出现频率。Verifier 只保证「引了 Pack 里的子串」，**不保证 Pack 是按用户原问从库中取出的**。因此改写可以产出「引文合法、选题已被模型带偏」的答。

**近端（Phase A）**：仍允许 §3.5 / §4.3，但须克制：

1. **先**用用户原问做 Pass-1；改写只补假阴性（繁简字形、英译用词），不抢路由、不新开书箱  
2. 改写宜少（1–3 条）、宜短、宜字形/专名，不宜把现代题「翻译」成一套现成教义  
3. Pack 保留用户 `query`；分析须能回到原问，不得只围着改写词打转  
4. 禁止把 `--extra-queries` 写成库中未必有的整句「原文」

**后续（Phase B/C，优化方向）**：扩词应 **忠于数据库、忠于原文**，而不是加重模型改写：

| 手段 | 作用 |
|------|------|
| 对**原问**做稀疏/稠密检索 | 让库自己说话，少经过模型范畴 |
| 扩词须 **库内可核验** | extra 必须是某 chunk / curated 标签 / BOOKLIST 别名的子串，否则丢弃 |
| 命中溯源 | 标明 hit 来自原问还是改写；改写独有的块降权或仅作辅证 |
| 专名别名表 | 从库统计或人工核验，不从模型记忆生成 |

目标：假阴性靠**字形折叠 + 库证扩词 + 向量**补；假阳性靠「未在库中出现的改写词不得进检索」。

## 4. 中英应对（中 ↔ 英）

### 4.1 分书语言，不混检同一套词

| 书 `retrieval_language` | 检索用 | 命中文本 |
|-------------------------|--------|----------|
| `zh` / `classical_zh` | 中文（经繁简折叠） | 中文原文 |
| `en` | **英文词**（由中文意图扩出） | 英文原文 |

中文书 **不用** 英文词去扫史记；英文书 **不用** 把中文词拿去对 Marriott 正文（对不上）。

### 4.2 中文问题 → 英文检索词（扩写表）

Router / `expand_terms` 维护 **意图正则 → 英文关键词**（可增补，禁止临时瞎编书中没有的「名言」）：

| 中文意图 | 英文检索词 | 目标书 |
|----------|------------|--------|
| 爱/怕/畏惧/仁慈/残暴 | loved, feared, cruelty, clemency | the_prince |
| 新主/新岗位/站稳 | new principalities, own arms, fortune | the_prince |
| 雇佣/外援/同盟 | mercenaries, auxiliaries, faith | the_prince |
| 可控/情绪/职责/苦难 | opinion, duty, obstacle, mind | meditations |

### 4.3 模型查询改写（英文侧，Skill 驱动）

意图表覆盖有限。当目标含 `the_prince` / `meditations`，且满足任一条件时，Skill **可以**把简体问题改写成英文检索问句/关键词再检索（权宜，见 §3.6）：

触发条件：

1. Router 打开 strategy/cultivation 且会扫英文书  
2. 仅靠 `ZH_TO_EN` 表扩词后英文书 0 命中或 `low_confidence`  
3. 问题是现代职场隐喻，需映射到书中范畴（新主、雇佣军、可控等）

改写产出：

| 产出 | 用途 |
|------|------|
| 1–3 条**英文**检索短句 | 贴近 Marriott / Long 译本用语 |
| 3–8 个英文关键词 | 喂给 `retrieve.py --extra-queries` |

约束同繁体侧：改写只服务匹配；**论据只能是 Pack 里的英文原句**；回答分析仍用中文。  
英文改写同样受 §3.6 约束：不得用模型偏好把问题锁进 loved/feared 等少数金句。

### 4.4 英文问题（少见）

若用户直接用英语提问：英文词原样检索英文书；中文书可尝试专名（Xiang Yu 等）—— Phase A 不做完整英→中专名表；不足时用模型改写出简/繁检索词，未覆盖则 L0。

### 4.5 回答形态（强制）

见 [11-bilingual-retrieval.md](11-bilingual-retrieval.md)：

1. 原文依据：英文原句 + locus（章节号）  
2. 括号意译：标明「意译非原文」  
3. 据文分析 / 方略：中文  

繁体中文底本同理：依据栏贴繁体原句；分析用简体中文，不把繁体「翻译」成简体冒充原文。

## 5. 生成与校验怎么接

```text
用户问（简体中文）
    → Router 开书箱
    → Pass-1：expand_terms + fold + ZH_TO_EN 表（确定性）
    → 若目标含繁体/英文书 且 Pass-1 弱命中：
         Skill 驱动模型 → rewritten_queries（繁体短句 / 英文短句+关键词）
         → Pass-2：retrieve --query 原问 --extra-queries 改写
    → Pack.chunks[].text = 底本原文（未折叠、未翻译）
    → 模型：引 Pack 原文 + 中文分析（改写句不得进「原文依据」）
    → Verifier：引文 ⊆ 原文（区分大小写与繁简，不做折叠）
```

Pack 字段：

| 字段 | 含义 |
|------|------|
| `query` | 用户原问（简体） |
| `rewritten_queries` | 模型/确定性改写列表（审计用） |
| `expanded_terms` | 实际用于匹配的词 |
| `retrieval_language` | 本块底本语言 |
| `match_mode` | `zh_fold` / `en` |

## 6. 验收用例

必须同时满足「能搜到」和「引用仍是原文」：

| # | 查询 | 期望 |
|---|------|------|
| 1 | `司马光` | 命中通鉴中含 `司馬光` 的块；依据栏不得改成「司马光曰」除非原文就是简体 |
| 2 | `玄武门` | 若底本为 `玄武門` 或相关纪事，靠折叠命中；无该三字则不可编造 |
| 3 | `被人爱戴还是畏惧` | 命中 *The Prince* 英文 `loved`/`feared`；依据为英文 |
| 4 | `通过实践而发现真理` | 命中实践论简体原句 |
| 5 | 故意引用简体「司馬光→司马光」去校验通鉴繁体块 | **Verifier FAIL** |
| 6 | 现代隐喻问权力（表未覆盖） | Skill 改写出英文检索词后能命中 Prince；依据仍是英文原句 |
| 7 | 把改写繁体短句写进「原文依据」 | **禁止**；Verifier / 人工审均判违规 |

## 7. 阶段

| 阶段 | 繁简 | 中英 |
|------|------|------|
| **Phase A（当前）** | fold + 双写；弱命中时 **Skill 模型改写（权宜）**；原文不改 | 意图表 + 模型英文改写（权宜）；引英答中 |
| **Phase B** | OpenCC；`text_fold`；**库证扩词**（改写词须在 chunks/curated 出现） | 原问向量/BM25；扩词表只收库内词 |
| **Phase C** | 异体/通假；从库统计专名别名 | 英汉对齐句对（可选，不作假原文）；改写独有命中降权 |
