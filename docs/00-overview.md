# 00 · 总览：目标、原则、与 skill 关系

## 要解决什么问题

个人 skill `shi-shi-qiu-shi` 目前提供的是：

- 决策工作流（事实 → 主矛盾 → 方略 → 实践）
- 经籍**用法索引**与透镜

它**不包含**典籍全文，因此无法保证每条判断都忠于可核对原文。模型可能用参数记忆「像那么回事」地答题，出现假引文或错篇名。

本项目要把能力升级为：

**原文接地（Grounded）的实事求是咨询** = 受控语料 + 检索 + 强制引用 + 校验 + 人生方略模板。

**产品定位（已升级）：** 对外应视为 **元 skill**——先按用户书单**构建**可校验知识库，再以 agent-skill 形式**据库答问**。语料正文不随 skill 分发；可复用的是建库协议与检索/校验脚本。详见 [13-meta-skill.md](13-meta-skill.md)。

## 设计原则

1. **真相源在文件，不在权重**：论据只能来自 `corpus/` 中可定位文本。  
2. **失败可见**：检索不足时明确拒答「以典为据」的部分，而不是补全。  
3. **协议重于模型聪明**：生成顺序与校验脚本比调温度更重要。  
4. **渐进保真**：先 Phase A 精选篇目可复核，再扩全书与向量。  
5. **方法迁移，不作宣教**：毛选等用于认识论与方法；权术类典籍必须带伦理/法治边界。  
6. **建库与答问同属一 skill**：无 `ready` 语料时只允许 BUILD / L0，禁止假引典。

## 与仓库其他部分的关系

| 位置 | 角色（过渡期） |
|------|----------------|
| `~/.cursor/skills/shi-shi-qiu-shi/` | 对话入口；目标含 Mode BUILD + Mode COUNSEL |
| `05-shi-shi-qiu-shi/`（本目录） | 开发沙盒 + 默认实例；协议真源在 `docs/`，脚本在 `scripts/` |
| 用户本地 `corpus/` | BUILD 产物；**不**作为 skill 分发包内容 |
| `00-strategy/` 等 | 职业副业执行包；本系统可为其提供「人与局」判断，不替代表格填写 |

长期：脚本与精要 docs **并入 skill 包**；本目录可收缩为示例实例（见 [13](13-meta-skill.md) §6）。

## 成功标准（产品级）

- 用户提出人生/职业两难 → 系统返回带 **可点击/可搜索 locus** 的原文依据  
- 抽查任意「原文依据」→ 能在 `corpus/chunks` 中精确找到  
- 故意问库外冷僻内容 → 系统拒引或声明覆盖不足，而非编造  

## 非目标

- 替代学术校勘与历史学研究  
- 提供违法、伤害他人的操作指南  
- 在未收录全文时宣称「已吃透二十四史」
